# 2026-10-03 Memur 修复

## Bug：录音处理后界面卡在"处理中"，无法开始新录音（v1.0.0 → v1.0.1）
- 根因：RecordingService.stopRecording() 把 companion 静态 _state 置为 RecState.Processing 后 stopSelf()，全流程结束无任何代码复位回 Idle；onDestroy 只处理 Recording 状态。
- 修复 4 处：
  1. RecordingService：submit 交接完成后立即 _state=Idle；
  2. PipelineEngine：新增 job 句柄（submit 前取消旧任务）+ cancelProcessing()；
  3. HomeScreen RecordArea："处理中"显示改由 pipeline.pending（Transcribing/LlmThinking）驱动，不再依赖永不复位的 RecState；
  4. ResultSheet：状态弹层（识别中/整理中）可下拉关闭或点"取消本次处理"，Error 弹层可关闭；Confirm 弹层保持不可误关（有明确按钮）。
- 产物：碎碎念-Memur-v1.0.1.apk（versionCode 2），release 构建通过、aapt 验签 OK。
- 经验：静态（companion）StateFlow 做服务状态机时，必须保证每个状态都有出边；模态 ModalBottomSheet 若 onDismissRequest 为空 lambda 会吞掉返回手势且锁死界面。

## v2.0.3：修复启动闪退（restoreHistory NPE）
- 症状：真机启动即闪退，NPE at AgentLoop.restoreHistory（history 字段为 null）。
- 根因：init 块写在类体中部，而 history 字段声明在其后；scope.launch 的回灌协程跑在 Default 线程池，可能在构造函数完成前执行，读到未赋值的 history。时序竞态非必现。
- 修复：init 块移到类体最末（全部属性初始化完成后再启动协程）。
- 验证：adb 直装真机，4 次冷启动进程全存活，crash buffer 0 条。
- 经验：构造函数里 launch 协程访问成员字段时，init 块必须放在全部属性声明之后。
- 备注：当日该版本的 cp/日志命令曾静默失败（v2.0.2 旧 APK 残留、日志缺失），已补记并清理。

## v2.0.4：修复回答结束瞬间闪退（StatusBar ClassCastException）
- 症状：用户提问，AI 回答完成时闪退。logcat: ClassCastException: AgentStatus$Idle cannot be cast to AgentStatus$Working，位于 ChatScreen StatusBar。
- 根因：v2.0.1 美化时 StatusBar 包进 AnimatedVisibility。回答结束时 status 从 Working 变回 Idle，但收起动画（约 200ms）期间内容仍会以新状态重组，else 分支 `(status as AgentStatus.Working).activity` 强转崩溃。AnimatedVisibility 退出动画期间内容仍被求值，必须容忍"已隐藏"状态。
- 修复：remember 最近一次工作文案（lastActivity），else 分支不再强转。
- 验证（真机 adb）：v2.0.4 安装后冷启动正常；用户真实语音提问"大唐项目，我住在什么位置？"，完整链路（ASR→LLM→grep 检索→回答→状态条收起）跑通，正确回答笔记内容（14楼三单元06号），60 秒盯守进程存活、crash buffer 0 条。
- 经验：**AnimatedVisibility 内容里的类型强转是闪退高发点**——退出动画期间旧内容以新状态重组，任何 `as X` 都可能拿到隐藏态的值。
